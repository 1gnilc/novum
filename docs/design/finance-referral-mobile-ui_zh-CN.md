# 客户财务与推荐移动端 UI 规范

[English](finance-referral-mobile-ui.md)

## 状态与权威性

本文档是客户财务与推荐范围内可直接用于实现的移动端页面和交互设计。[`customer-finance-referral`](../plans/customer-finance-referral/README.md) 中的业务规则仍具有权威性。本文档决定展示方式、路由组成、控件、状态、响应式行为、本地化及参考资源的使用；不得重新解释业务不变量。

本设计归仓库所有且可移植。开发者无需采集电脑、AdsPower 安装、已认证的参考站点会话或仓库外文件即可实现。

## 持久输入

- 业务规范：[`customer-finance-referral`](../plans/customer-finance-referral/README.md)
- 参考页面审查：[`mobile-reference-pages_zh-CN.md`](mobile-reference-pages_zh-CN.md)
- 实测视觉参考：[`ui-style-guide`](ui-style-guide/README_zh-CN.md)
- 参考资源清单：[`ui-style-guide/data/assets.json`](ui-style-guide/data/assets.json)
- Vant 支付密码控件：[`PasswordInput`](https://vant-ui.github.io/vant/#/zh-CN/password-input) 和 [`NumberKeyboard`](https://vant-ui.github.io/vant/#/zh-CN/number-keyboard)

下文会重复列出精确的公开参考 URL，以及采纳或拒绝的行为。外部页面是证据，不是运行时依赖。

## 体验方向

移动端应用是紧凑的操作型产品，不是营销落地页。客户应能直接识别余额、推荐进度、记录状态和下一步操作，无需浏览装饰性内容。

### 视觉系统

- 保留现有的浅色、深色和跟随系统主题能力。
- 将参考配色作为品牌输入，而不是把页面处理成单一色调。
- 浅色模式使用中性的 `#F5F7FA` 画布和白色工作表面。`#0E2D42` 与 `#1E2947` 仅用于品牌页头和导航。
- 深色模式使用 `#0E2D42` 画布、`#1E2947` 导航和 `#334364` 工作表面，并通过中性边框和语义状态色打破蓝色系的单调感。
- 主要操作使用 `#FB6F30`，选择与进度使用 `#6757D4`，成功使用 `#8CDE4C`，破坏性操作或失败状态使用 `#FA3747`。
- 使用现有系统无衬线字体栈，不要使用参考站点意外采用的 Times 默认字体。
- 字间距保持为 `0`。不要根据视口宽度缩放字号。
- 说明文字使用 12px，辅助文字 14px，正文与控件 16px，页面标题 18px，财务摘要金额最大 24px。
- 使用 8px 间距节奏；仅紧密关联的标签/值对使用 4px。
- 普通控件和卡片使用 4px 或 8px 圆角。只有圆形头像和状态点常规使用全圆。
- 使用边框和表面对比代替装饰性阴影。弹出层可以使用一个克制的阴影。
- 金额、计数、手机号、账号、交易 ID 和时间戳使用等宽数字。

### 布局

- 支持 320px 及以上宽度的视口。在 360x800、430x932 和 768x1024 CSS 像素下验证。
- 页面内容最大宽度为 560px，在较宽的移动端或平板视口中居中。
- 小于 360px 时使用 12px 水平边距，360px 起使用 16px，600px 起使用 20px。
- 主标签栏固定在底部并包含安全区内边距。二级页面隐藏主标签栏。
- 仅对页面唯一的主要操作使用底部吸附操作区。页面底部内容内边距应等于操作区高度加安全区内边距。
- 窄屏上的统计和金额网格使用两列。从 480px 起，如果所有格式化后的 NGN 值都能完整显示，可使用三列金额网格。
- 绝不在卡片中嵌套卡片。页面分区不加外框；重复记录可以使用带边框的行或独立卡片。
- 交易 ID 和账号使用 `overflow-wrap: anywhere` 换行；绝不根据视口宽度缩小字号。
- 每个触控目标至少为 44x44 CSS 像素。

### 控件

- 使用移动端已有的 Vant 组件：Form、Field、Button、Cell、ActionSheet、Dialog、Tabs、PullRefresh、List、Skeleton、Empty、Uploader、PasswordInput 和 NumberKeyboard。
- 熟悉的操作使用 Vant 图标。仅返回、新增、复制、显示/隐藏、编辑、删除和刷新等熟悉命令可使用纯图标按钮；控件必须有无障碍名称，图标含义不明显时还应提供提示。
- 多选一使用单选行，记录状态视图使用标签页，选项集合使用菜单或选择面板，对话框仅用于破坏性确认或凭据验证。
- 禁用控件必须保持尺寸和标签不变。加载指示器不得改变按钮或行的尺寸。
- 不要在应用内展示功能说明、键盘快捷键、视觉设计评论或教程文案。

## 共享外壳与状态

### 主导航

- 按首页、市场、团队、资金、我的顺序保持可见。
- 使用稳定的 Vant 图标：首页使用 home，市场使用 trend/market，团队使用 friends/team，资金使用 balance/fund，我的使用 contact/my。
- 活动标签使用橙色主色，非活动标签使用低强调中性色。
- 标签文字保持可见，不使用仅图标的标签导航。
- 首页和市场不属于本功能的工作业务定义。

### 受保护路由提示

- 认证前不得渲染任何受保护的业务数据。
- 展示一个操作面板，以登录为主要操作、取消为次要操作。
- 登录应保留目标路由。取消则将路由替换为首页。
- 不要创建认证路由守卫；由路由派生的外壳负责该提示。

### 数据状态

每个数据页面都必须定义以下状态，且不得改变布局尺寸：

- 初始加载：使用内容形状的骨架屏，而不是无限显示的居中加载指示器。
- 刷新中：保留当前内容并显示 PullRefresh 进度。
- 加载更多：追加一个固定高度的加载行。
- 空状态：使用简短的本地化标题，最多一句说明；存在恢复方式时提供一个相关操作。
- 可恢复错误：显示简短的本地化错误及重试操作。
- 无法访问的记录：对不存在和属于其他客户的资源统一展示一个中性结果，并提供前往所属列表的导航。
- 过期的变更输入：保留业务错误、清除秘密值、重新加载权威数据，并只保留仍有效的非秘密选择。
- 提交中：在请求结束前锁定可变控件和主要操作。
- 超时或连接中断后的未知变更结果：绝不自动重试；引导客户前往权威列表，或在再次尝试前重新加载资源。

### 反馈

- 本地校验使用字段内联错误。
- 复制、保存和普通操作成功时使用简短 toast。
- 对需要用户决策的拒绝、锁定、不可访问、数据过期或结果未知状态，使用持久的内联结果或对话框。
- 展示后端已本地化的业务错误，不显示内部异常文本。
- 所属请求成功提交前不得展示成功状态。

## 认证页面

### 登录

- 使用包含仓库自有 Novum Logo 的紧凑品牌页头，不使用 Hero 区或卡片。
- 在导航栏中放置返回和语言操作。
- 字段顺序为国际区号加本地手机号，然后是密码。
- 国际区号渲染为在视觉上连接手机号字段的定宽选择器。默认使用 `+234`，仅提供 `+1` 和 `+234`。
- 当前密码字段应遮罩显示，并提供可见性图标。
- 登录按钮保持在正常文档流中；仅在键盘会遮挡按钮的短视口中吸附。
- 注册文字操作紧跟在登录按钮下方。
- 重新登录失败时保留当前客户会话。只有新的登录和客户信息加载都成功后，才替换本地会话数据。

### 注册

- 复用登录页的品牌页头和表单几何，使两个页面形成同一流程。
- 字段顺序为国际区号加本地手机号、密码、确认密码和邀请码。
- 新密码控件应遮罩显示并提供可见性图标。
- 邀请码可显示为六格数字字段，或使用等宽数字的单个数字字段；必须保留前导零。不要为邀请码使用支付密码键盘组件。
- 从路由查询参数预填 `inviteCode`，并保持可编辑。
- 注册按钮放在表单后，登录文字操作放在其下方。
- 自动登录期间，将按钮标签替换为尺寸稳定的登录中状态。如果自动登录失败，只携带手机号身份导航至登录页。

## 团队页面

### 团队概览

- 使用克制的顶部区域展示当前等级、当前等级费率、自动升级状态和下一等级进度。
- 不使用参考资料中的 `Member` 徽章；其措辞与推荐奖励等级冲突。改用 Vant 奖章/钻石图标及语义化颜色。
- 使用两列网格展示直接注册人数、合格直接推荐人数和团队总人数；必要时总人数跨越最后一行。
- 将 L1、L2、L3 显示为三条包含层级、数量和箭头的全宽行，避免三个狭窄卡片。
- 将邀请码和邀请链接展示为两个复制行。显示的 URL 可以换行；复制控件固定在行末。
- 将推荐等级详情作为最后一个导航行。
- 进入页面时刷新并支持下拉刷新。有效的零计数响应属于正常内容，不是空状态。

### 团队成员

- 使用与路由参数同步的 L1/L2/L3 分段控件。切换分段时替换路由参数并重新加载第一页。
- 每个成员渲染为紧凑行，包含 40px 头像、后端遮罩后的昵称、后端遮罩后的手机号、注册时间，以及仅 L1 显示的合格徽章。
- 没有头像时使用中性头像占位图。
- 列表保持只读，并使用无限加载。

### 推荐等级详情

- 首先展示当前等级、合格直接推荐人数和自动升级状态。
- 使用垂直的四步进度，而不是四张独立的大卡片。
- 每一步显示等级名称、门槛、费率和已达到/当前/未达到状态。
- 在当前步骤下方显示一个紧凑的下一等级进度条。Diamond 使用最高等级终态结果。
- 在进度下方用简洁的带标签行展示已确认的奖励与升级规则。
- 不使用参考等级图片，因为其中包含 `Member` 和固定数字标签。

## 资金页面

### 资金概览

- 使用一个余额区域展示 `NGN` 可用余额，字号最大 24px。
- 在余额下方直接放置等宽的充值和提现两个主要操作按钮。
- 使用两列定义行展示累计充值本金和累计已支付提现金额。
- 将充值历史、提现历史和余额账本显示为全宽导航行。
- 不展示最近记录或冻结余额。

### 发起充值

- 分区顺序为可用余额、金额选项、可用渠道、所选摘要和主要操作。
- 使用尺寸稳定的响应式金额网格。每个选项展示本金和字号更小的正向赠送标签。
- 选择金额后，将渠道显示为全宽单选行。`title` 是渠道的唯一身份标识。
- 将本金、赠送和入账金额显示为三行定义列表，确保较长的格式化值不会相互碰撞。
- 在短屏幕中将主要操作吸附在安全区上方。
- 发起请求待处理时，将按钮内容替换为定宽加载状态，直至浏览器开始导航。

### 充值历史

- 使用可水平滚动的全部/待处理/已支付/已取消标签页。
- 每笔充值渲染为一个带边框的记录行：第一行显示状态和入账金额，第二行显示交易 ID 和渠道，下方显示本金/赠送金额及时间。
- 语义状态色只用于状态标签，不用于整张卡片。
- 点击记录行打开详情。不要在记录行放置继续支付操作。

### 充值详情

- 使用紧凑的状态页头，后接交易 ID、渠道、本金、正向赠送金额、入账金额、创建时间和支付时间的定义行。
- 在交易 ID 旁放置复制操作。
- 待处理且有 URL 时提供一个继续支付按钮。待处理但无 URL 时展示禁用的不可用状态及刷新操作。
- 已取消时提供一个发起新充值操作。已支付时不提供支付操作。

### 提交提现

- 分区顺序为处理提示、可用余额、提现账户、金额选项、费用摘要、支付密码和提交操作。
- 使用账户选择面板，以单选行显示持有人、银行和完整账号。
- 使用尺寸稳定的金额网格，不可用值原位禁用。
- 使用定义列表展示申请金额、费率、费用金额和净额。
- 只有账户和金额有效后才显示 PasswordInput。NumberKeyboard 连接该控件，并且不得遮挡费用摘要或提交操作。
- 输入全部六位数字后仍需明确点击提交，不得在键盘输入完成时自动提交。

### 提现历史

- 使用可水平滚动的全部/待处理/已拒绝/已批准/已支付标签页。
- 首先展示状态和净额，然后是银行和完整账号，最后是申请金额、费用和申请时间。
- 点击记录行打开详情。记录行中的任何操作都不得更改或重新提交提现。

### 提现详情

- 使用紧凑的状态页头和按顺序排列的状态时间线。
- 在一个无外框分区中展示不可变账户快照，在另一个分区中展示金额明细。
- 在提现 ID 旁放置复制操作。
- 已拒绝时展示原因及资金已释放提示。已批准时展示等待手动打款提示。已支付时展示支付时间。
- 将刷新放在导航操作或一个次要按钮中；绝不自动轮询。

### 余额账本

- 使用全部/收入/支出分段控件，后接一个类型筛选菜单。
- 每行首先显示本地化类型标题和带符号金额，然后是变更前后余额，最后是时间。
- 收入符号使用成功色，支出符号使用危险色，正文保持中性色。
- 不增加详情入口；每行信息完整且不可交互。

## “我的”页面

### 我的概览

- 在一个紧凑资料页头中展示 80px 头像、昵称、完整客户手机号身份和可选邮箱。点击整个页头进入编辑资料。
- 头像为空时使用仓库的中性头像占位图。
- 将提现账户、修改登录密码和语言显示为全宽导航行。
- 在语言行显示当前语言。打开现有语言选择面板，并通过移动端偏好设置立即应用所选语言。
- 将退出登录作为底部分隔开的危险文本命令，不要放入资料页头。
- 使用对话框确认退出登录。确认后调用后端，始终清除本地客户会话数据，并将路由替换为不带重定向目标的登录页。
- 用户信息加载失败时显示重试结果，不得把过期客户详情渲染为当前信息。
- 不显示角色、权限、内部客户 ID、用户名、财务汇总或推荐统计。

### 编辑资料

- 将当前头像显示为带相机编辑图标的 80px 圆形。使用托管图片上传器，并在尺寸稳定的头像框上展示上传进度。
- 有头像时提供带小型删除图标的移除头像操作；仅当客户在当前编辑会话中尚未替换头像时确认移除。
- 字段顺序为昵称和可选邮箱。将客户手机号身份显示为可编辑字段上方的只读身份行，而不是禁用的表单输入框。
- 按已确认规则归一化并校验昵称和邮箱。只在接近字符数限制时显示计数。
- 没有归一化后的值发生变化，或图片仍在上传时，禁用保存。
- 成功后更新已认证客户信息，显示成功 toast，并返回我的概览。
- 带有未保存的归一化更改离开时，确认放弃或继续编辑。
- 上传失败时保留此前已提交的头像并允许重试。

### 提现账户

- 在导航栏使用带无障碍名称的新增图标，并在空状态中提供相同的新增账户操作。
- 不分页列出有效账户。每行显示持有人、银行名称和代码，以及完整的归一化账号。
- 银行已禁用的账户应标记为不可用于提现，但其管理操作仍保持可用。
- 选择一行时打开小型操作面板，包含编辑账户、修改支付密码和删除账户。不要暴露多个拥挤的行内按钮。
- 删除账户时打开破坏性确认对话框，其中包含账户摘要和一个遮罩显示的当前登录密码字段。
- 确认删除后锁定对话框。成功后移除该行。超时或连接中断时关闭秘密输入、重新加载列表，并且绝不盲目重试删除。

### 创建提现账户

- 字段顺序为持有人、提现银行、账号、当前登录密码、新支付密码和支付密码确认。
- 由于初始化列表包含数百家银行，提现银行应在可搜索面板中选择。按银行名称或代码在本地进行不区分大小写的搜索；只能选择已启用银行。
- 国家无关的账号使用普通文本输入框。移动端在预览时去除空白并将 ASCII 字母转为大写，后端仍为权威来源。
- 当前登录密码使用 `current-password` 自动填充语义并遮罩显示。
- 依次通过 PasswordInput 和 NumberKeyboard 输入支付密码及确认密码；同一时间只显示一个输入界面。确认密码仅存在于移动端。
- 账户字段、登录密码和两次一致的六位支付密码均填写完成前，保存保持禁用。
- 成功后清除所有秘密值、显示成功 toast，并将路由替换为提现账户列表。
- 如果存在重复的有效银行账户身份，留在当前页面，清除两类凭据，并高亮银行和账号。
- 超时或连接中断时清除所有凭据并返回提现账户列表；再次尝试前先确认创建是否已提交成功。

### 编辑提现账户

- 预填持有人、当前银行和归一化账号。绝不返回或预填支付密码。
- 使用与创建页相同的可搜索已启用银行面板。
- 如果当前银行已禁用，展示其历史值，但保存前必须选择已启用银行。
- 至少一个归一化账户字段发生变化后，显示当前支付密码输入。
- 只有数据已变化且完整输入六位当前支付密码后，保存才可用。
- 不要在此页面放置支付密码替换字段；使用专用路由。
- 密码错误或被锁定时只清除密码并保留编辑内容。成功时清除密码、更新列表并返回提现账户。
- 超时或连接中断时清除密码，并在再次尝试前重新加载账户。

### 修改支付密码

- 将账户的持有人、银行和完整账号显示为只读上下文。
- 使用同一个 NumberKeyboard，通过三个连续 PasswordInput 阶段收集当前支付密码、新支付密码和新密码确认。
- 允许任意六位 ASCII 数字，也允许新值与当前值相同。
- 确认密码只存在于移动端。仅发送当前支付密码和新支付密码。
- 当前密码错误或被锁定时，清除全部支付密码值，但保留账户上下文。
- 成功后清除全部值、显示成功 toast，并返回提现账户。
- 不提供重置、找回或联系管理端入口。

### 修改登录密码

- 字段顺序为当前密码、新密码和新密码确认。
- 使用带可见性图标的遮罩字段，并采用恰当的当前/新密码自动填充语义。
- 对新密码应用已确认的强密码规则，并允许它与当前密码相同。确认密码仅存在于移动端。
- 提交期间锁定保存，绝不自动重试。
- 成功后清除所有本地客户会话数据，因为后端会撤销所有会话；随后将路由替换为登录页并展示密码已修改结果。
- 超时或连接中断时清除所有密码字段和本地客户会话数据，然后打开登录页并显示结果未知消息；不得假定旧会话仍然有效。
- 不提供重置或找回功能。

## 本地化与格式化

### 支持的语言区域

仅支持现有的四种界面语言区域：

- `en-US`：英语，默认回退语言
- `zh-CN`：简体中文
- `ha-NG`：豪萨语
- `yo-NG`：约鲁巴语

国际区号与界面语言区域相互独立。绝不能根据 `+234` 推断豪萨语或约鲁巴语，也不能根据 `+1` 推断英语。

### 消息归属

- 将页面标签、控件文本、空状态、状态标签和账本标题放在移动端 `vue-i18n` 资源中，并按内聚资源分组。
- 使用所属后端消息包提供的、已在后端本地化的稳定业务错误。不要在移动端复现内部异常字符串。
- 不依赖管理端动态消息或 `@vben/locales`。
- 使用带插值的完整翻译字符串。不要围绕计数、金额、时间、名称或状态拼接翻译片段。
- 每个语言文件必须具有相同的键集合。CI 测试负责比较语言键是否一致。
- 豪萨语和约鲁巴语标签至少允许换行两行。按钮或标签页不得裁剪翻译后的标签。

### 领域格式化

- 金额使用 `Intl.NumberFormat` 格式化，配置 `currency: 'NGN'`、`currencyDisplay: 'code'`，并固定保留两位小数。
- 百分比固定保留两位小数，后接 `%`。
- API 时间点通过现有 Day.js 语言管线，以设备本地时区展示。必须包含绝对日期和时间，不得只使用相对时间。
- 提现处理时间窗口字符串严格按后端 `HH:mm` 值展示，不进行时区转换。
- 在已确认允许展示的场景中，显示已认证客户的完整手机号身份。团队成员手机号和昵称只能使用后端提供的遮罩值。
- 不要在可见文案中直接显示枚举值；通过语言资源映射充值、提现、账本、等级、方向和合格状态。

## 资源决策

实现时，只将选中的文件复制到所属移动端资源目录，并按产品用途重命名。运行时代码绝不从 `docs` 导入，也绝不热链接参考 CDN。

### 批准候选

- `ui-style-guide/assets/images/logo-novum.png`：用于紧凑的认证和品牌标识。
- `ui-style-guide/assets/images/empty-state.png`：在验证两种主题下的对比度后，用于通用空状态或不可访问状态。
- `ui-style-guide/assets/images/no-data.png`：如果在所需尺寸下仍清晰可读，可作为记录列表空状态的备选。
- 移动端已有的语言旗帜和头像占位图仍是权威来源；不要从参考目录重复复制。
- 在复制具有相同含义的位图图标前，优先使用已安装的 Vant 图标。

### 禁止使用的参考资源

- `banner-invite.png`：包含仅首次充值和固定 10% 奖励文案，与 Novum 规则冲突。
- `qr-invite-large.jpg` 和 `qr-invite-small.jpg`：包含账户特定的已采集二维码。
- `vip-badge-gold.png`、`vip-badge-platinum.png`、`vip-badge-diamond.png`、`vip-badge-1-static.png`、`vip-level-2-card.png` 和 `vip-level-3-card.png`：包含 `Member`、固定数字或过时的 VIP 语义。
- `captcha-sample.png`、`captcha-register.png` 和 `captcha-register-alt.png`：验证码不是 Novum 需求。
- `login-background.png`：包含可见的素材水印，不符合生产品牌资源要求。
- `fontello-icons.ttf`：Vant 已经负责图标体系，不要再增加第二套图标字体。
- 任何包含手机号、邀请码、余额、交易 ID 或账户特定状态的已认证截图或资源。

## 验收检查

- 在浅色和深色主题下，分别以 360x800、430x932 和 768x1024 视口验证每条路由。
- 验证标签栏、吸附操作、NumberKeyboard、对话框、选择面板、长翻译、金额、手机号、账号或交易 ID 不会与其他控件重叠。
- 验证受保护页面不会在未认证提示后方渲染业务数据。
- 验证所有表单都在 `finally` 中恢复加载锁，并在文档规定的结果下清除秘密字段。
- 验证每个列表都有初始加载、刷新、加载更多、空、错误和结束状态。
- 验证所有纯图标控件都有无障碍名称；原生语义未提供键盘激活能力时，应自行提供。
- 验证焦点始终可见、对话框和选择面板正确约束焦点，且返回操作会回到文档规定的父级。
- 验证四个语言包的键集合一致，且豪萨语和约鲁巴语标签换行时不会被裁剪。
- 使用具有代表性的长值和零值验证 NGN、百分比、UTC 时间点展示及处理窗口格式。
- 验证所选仓库资源已复制到移动端，且运行时没有任何引用指向 `docs` 或外部资源主机。
