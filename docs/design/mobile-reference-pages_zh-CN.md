# Novum 移动端参考页面审查

[English](mobile-reference-pages.md)

## 目的

本文档保存移动端参考站点审查中可复用的结论。它是产品探索的输入，不是实现规范，也不要求逐像素复刻来源站点。

由此形成、可直接用于实现的页面与交互决策维护在 [`finance-referral-mobile-ui_zh-CN.md`](finance-referral-mobile-ui_zh-CN.md) 中。该文档内容自洽，在 UI 实现中优先于本观察性审查。

- 来源：`https://www.novumaivip.com`
- 采集日期：2026-08-08
- 必需的采集环境：AdsPower 配置文件 37 / `k1f658vy`
- 采集视口：430 x 932 CSS 像素
- 采集模式：已认证的只读导航；未提交充值、提现、绑定账户、修改密码或其他会产生变更的表单
- 视觉配套资料：[`ui-style-guide`](ui-style-guide/README_zh-CN.md)
- 仓库自有资源：[`ui-style-guide/assets`](ui-style-guide/assets)

采集过程中观察到的登录凭据和账户特定值已被有意排除。以下结论内容自洽，确保实现不依赖采集电脑、其 AdsPower 安装或有效的参考站点会话。

## 可复用的交互结论

### 认证

- 国际区号应在视觉上与本地手机号输入框分离。
- 注册时将确认密码保留为移动端表单校验；它不是额外持久化的凭据字段。
- 参考注册页包含图形验证码和隐私协议。二者均不是已确认的 Novum 需求，后续未作出决策前不得实现。
- 参考页面的密码文案采用较弱的 6-16 位字母数字规则。Novum 必须改用已确认的 8-64 位强客户密码规则。
- 直接导航到来源站点的登录和注册路由可能清除或替换来源会话。除非明确请求退出登录，否则 Novum 路由不得引入这一副作用。

### 个人中心与资金

- 复用紧凑账户摘要后紧跟清晰任务入口的思路。
- 不要照搬来源站点将所有财务操作放入个人中心、却让资金页保持未开放的信息架构。
- Novum 应将资金页作为余额、充值、提现和账本的实际工作区。“我的”页面应负责个人资料、提现账户、密码、语言和会话操作。
- 账户标识和金额摘要必须使用稳定标签及 NGN 格式，不得只展示裸数字。

### 充值

- 复用单页选择顺序：当前金额、预定义金额选项、可用渠道，然后是主要操作。
- 展示所选选项的充值赠送金额及最终充值入账金额；来源页面只展示本金。
- 使用货币格式化器和响应式网格。来源页面使用了过大的固定单元格和无分组的大数字。
- 渠道选择采用单选/勾选指示器，并使整行都可触控。
- 如果主标签栏会与主要操作竞争空间或遮挡它，聚焦支付表单时不要展示主标签栏。
- 明确定义加载中、无可用渠道、不支持的渠道、发起失败和已支付状态，避免空白页面或无限加载指示器。

### 提现

- 复用以下顺序：提现账户、可用余额、提现金额选项、费用、净额，然后提交。
- Novum 必须使用预定义的提现金额选项，不得使用来源站点的自由金额输入框。
- 将配置的处理时间仅作为信息提示。不要复制来源站点的工作日限制、72 小时承诺、硬编码限额或硬编码的 25% 费用。
- 使用“提现手续费”，不要使用来源站点不一致的 `commission` 或法语 `Frais de traitement` 标签。
- 说明文案应简短、便于浏览；不要在表单下居中放置多段加粗长文。

### 提现账户

- 复用“列表 + 新增入口”模式及创建字段顺序。
- 为仅图标的新增操作提供无障碍名称和稳定的触控区域。
- Novum 支持多个提现账户，必须为每个账户提供编辑、删除和修改支付密码操作。
- 支付密码字段必须采用安全的六位数字输入。来源站点将其渲染为普通文本，不能照搬。
- 按已确认规则，Novum 在创建和删除时还必须要求客户登录密码。

### 账本与历史记录

- 复用紧凑的时间顺序记录行和轻量筛选器。
- 即使共享展示组件，充值历史、提现历史和客户余额账本仍应保持为不同的领域视图。
- 使用 Novum 已确认的状态和账本类型标签；`To be reviewed`、`Transfer rebate` 和 `commission` 等来源术语不是规范用语。
- 展示带符号金额、变更后余额、业务标签和时间戳，不得暴露仅供管理端查看的账本备注。

### 团队、邀请与推荐奖励等级

- 复用对邀请码和邀请链接的一键复制操作。
- 复用团队规模、合格直接推荐人数和 L1-L3 结果的紧凑概览，但避免使用三个狭窄卡片将标签挤进局促列中。
- 来源邀请页声称 L1-L3 奖励仅适用于首次充值。Novum 已确认的规则是每次成功充值都应用推荐层级奖励和推荐等级奖励，不得复用来源文案。
- 三个等级页面印证了已确认的初始值：Gold `3 / 13.00%`、Platinum `10 / 16.00%`、Diamond `20 / 20.00%`。
- 来源等级页面还要求外部聊天群、截图签到、手动申请和因不活跃而自动降级。这些行为不属于 Novum，并与已确认的自动、只升不降等级进度直接冲突。

### 密码

- 复用当前密码、新密码、确认密码和主要提交操作的结构。
- 确认密码仍是移动端表单字段；客户端校验成功后，不作为独立领域凭据发送。
- 不要复制来源站点客户全局的提现密码入口。Novum 的支付密码分别归属于各提现账户。
- 登录密码修改成功后，清除本地客户凭据并返回登录页，因为后端会撤销所有客户会话。

## 视觉方向

主要复用：

- 深色画布 `#0E2D42`；
- 导航表面 `#1E2947`；
- 工作表面 `#334364`；
- 主要操作橙色 `#FB6F30`；
- 选中强调色 `#6757D4`；
- 在语义合适处使用成功色 `#8CDE4C` 和危险色 `#FA3747`；
- 当符合已确认页面需求时，使用仓库已有的 Logo、导航图标、等级徽章、邀请图片和空状态资源。

应改进而非照搬：

- 使用应用的无衬线字体，而不是来源站点意外采用的 Times 默认字体。
- 普通卡片圆角保持在 8px 以内，避免来源站点 21-28px 的卡片和胶囊样式。
- 缩小过大的字段、金额和按钮，让一个视口承载有用的上下文。
- 使用中性色和语义对比，避免应用成为单一的深蓝色界面。
- 防止固定标签栏遮挡长内容或空状态。
- 用简洁的本地化行、提示或校验消息替换居中的红色长段文字。
- 提供稳定的加载、空、错误、禁用、选中和已提交状态；绝不让路由只呈现带加载指示器的空白画布。

## 可移植资源的使用

- 将 [`ui-style-guide/assets`](ui-style-guide/assets) 下的仓库文件视为可复用参考资源的持久来源。
- 实现时，只将选中的资源复制到所属移动端资源目录。运行时代码不得从 `docs` 导入，也不得热链接参考站点的 CDN。
- 在目标文件名中明确表达所复制资源的用途，避免用多个名称重复存放同一位图。
- 不要添加包含手机号、邀请码、余额、交易 ID 或其他账户数据的已认证参考截图。本报告已经在不保留这些值的前提下记录了其有用结构。
