# Keep Mobile independent from Admin application infrastructure

Build `apps/mobile` as an independent standard Vue application inside the existing pnpm and Turbo workspace. Do not depend on the Vben locale, Vite, TypeScript, layout, store, preferences, or UI infrastructure created primarily for Admin. Reuse `@vben/request` for its UI-independent RequestClient and authentication interceptors, `@vben-core/shared` for concrete data utilities, and `@vben/utils` for input normalization where Mobile has a concrete use case. Mobile owns a typed Pinia Preferences store whose persisted cache overrides application defaults; when the cache has no supported locale, the store resolves the first supported browser language and otherwise uses the application default. Mobile also owns its `coreSetup`, static `vue-i18n` message loading, Vant locale, and Day.js locale integration. Language changes update the Mobile Preferences store and then call `loadLocaleMessages(locale)`. Do not add the Admin preferences UI, layouts, dynamic messages, adapters, or unused configuration merely to resemble Admin.
