# Share session mechanics without sharing identity

Keep the implementation in `novum-core` under `com.gnilc.novum.session`. Extract opaque-token issuance, Redis AT/RT pairing, Lua-based atomic AT replacement, and Lua-based session deletion from the existing Admin implementation into package-private `SessionEngine`, `SessionPolicy`, `SessionRedisStore`, and `SessionTokenCodec` classes, with public `SessionTokenPair` as the domain-neutral result value. Replace `AdminSessionRedisCommands`, `AdminSessionTokenCodec`, and `AdminSessionTokenPair` with those types.

Keep public `AdminSessionManager` and `CustomerSessionManager` as separate entry points with separate token prefixes and Redis namespaces; controllers and services may use only their identity domain's manager. Keep `AdminSessionAuthenticationHandler` and `CustomerSessionAuthenticationHandler` beside each other in `com.gnilc.novum.auth`, and let each select only its own token prefix. Customer tokens must never authenticate as Admin tokens or reuse Admin Redis keys; existing Admin HTTP and session behavior remains unchanged.

Customer tokens use `customer.<userId>.<32 random bytes>` and Redis keys `customer:at:<userId>:<accessToken>` and `customer:rt:<userId>:<refreshToken>`. AT expires after 7 days and RT after 30 days. Refresh atomically replaces the paired AT while retaining the RT and its remaining TTL, so only one concurrent refresh for the same old pair succeeds; logout atomically removes the RT and its current AT. Separate logins create separate Customer sessions.
