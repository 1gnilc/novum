# Define Customer session access records

Create one built-in role with `code = 'customer'`, `name = '客户'`, `remark = '客户基础角色'`, and `built_in = 1`, and ensure every active `nv_customer` row has an active `az_user_role` binding to it. Initialization restores a logically deleted role or missing binding, while RBAC management cannot rename or delete the built-in role. Every role replacement and unbind entry point rejects removal of the `customer` binding instead of silently restoring it. Enforce the Admin and Customer requirements through an extensible role-assignment policy owned by the shared RBAC assignment boundary, with the Novum application supplying account-specific rules. This phase creates no `az_menu` or `az_role_menu` records for Customer.

Create exactly three built-in public permissions: `POST:/customer/login`, `POST:/customer/refresh`, and `POST:/customer/logout`, each with the matching path as `target_identifier`, `POST` as `target_qualifier`, and both `public_access = 1` and `built_in = 1`. Login accepts `{ username, password }`; refresh and logout accept the RT in `X-Refresh-Token`; login and refresh return `{ accessToken, refreshToken }`; protected requests send the AT as `Authorization: Bearer <accessToken>`. Invalid credentials use the existing `AUTHENTICATION_FAILED` business error, while an invalid or missing RT returns HTTP 401 for refresh and logout.

Create one built-in protected permission with `code = 'GET:/customer/user-info'`, `target_identifier = '/customer/user-info'`, `target_qualifier = 'GET'`, `public_access = 0`, and `built_in = 1`, and maintain one active `az_role_permission` binding from the built-in `customer` role to this permission. `GET /customer/user-info` requires a valid Customer AT and returns `id`, `createTime`, `userId`, `username`, `nickname`, optional `avatar`, and `roleCodes`; it omits password, status, deletion state, and the Admin-only `desc` and `homePath` fields. A missing or invalid AT returns HTTP 401.

Place Customer schema and default identity restoration in `deploy/sql/08_customer.sql`, and place the four permission records and the protected role binding in `deploy/sql/09_customer_permissions.sql`. Execute them after the existing `01` through `07` scripts without renumbering those scripts.
